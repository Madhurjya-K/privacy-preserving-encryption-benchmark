# Measurement protocol and interpretation

Primary question: selective Paillier aggregation avoids numeric plaintext on hybrid workers, but does its cost compare favorably with AES decrypt-then-analyze? No favorable performance outcome is assumed.

All four configurations share rows, fixed-point encoding, queries, grouping and manifest protection. PLAIN includes integrity manifest and storage preparation for fair serialization/integrity comparisons; it is not a zero-cost bare sum. AES-DEC encrypts entire records as AES-GCM tuples; this is broader than encrypting only numeric columns and must be reported. In Spark, AES-DEC decrypts inside worker map functions; Python smoke decrypts on the local process. H-CHAOS/H-GCM protect sensitive tuples and encrypt aggregation fields using Paillier.

The cloud workload is grouped and ungrouped SUM, COUNT(*) and AVG. COUNT(*) counts all rows; AVG divisor is the per-field non-null count. Null numeric ciphertexts expose missingness. All-null SUM and AVG are null. Rounding occurs before encryption using Decimal HALF_EVEN at scale 100. Results are compared across configurations; unit-test fixtures supply independently hand-computed negative/null results. H-GCM and H-CHAOS use the same integer aggregation mechanism. Worker group keys are JSON-canonical representations to avoid conflating numeric and string values.

Phases: owner key generation (separate); protection including bound check, encryption, canonical partition digests and HMAC; integrity verification; query (two workloads); owner aggregate decryption/averaging; protected serialization; protected whole-file SHA-256. Separate plain serialization and plain SHA-256 controls are measured but not subtracted. Samples record stages and Python memory peaks; initialization and source reading are outside them. Query time includes Spark scheduling and collect overhead. Spark startup is excluded. No network transfer is simulated. End-to-end reported by summary is the sum of the six measured stages, not an independent stopwatch.

Each configuration warms up once and runs ten repeats for public-data research, all using fresh encryption randomness/nonces. Keygen happens once per run rather than every repeat; configurations share one Paillier modulus. Tests and smoke use short insecure keys solely for tractability. Research requires 2048+ bits and rejects smaller defaults. Serial decimal-string Paillier ciphertexts are larger than packed binary 4096-bit ciphertexts: storage growth must be interpreted as implementation serialization, not primitive-only expansion.

Reports contain raw samples, median, linearly interpolated quartiles/IQR and seeded 2000-resample percentile bootstrap 95% intervals for medians. Overhead summaries use repeat-index ratios against reference samples and bootstrap those ratios. Sequential fixed-order execution is a known weakness: repeat indexes are not simultaneous paired trials, configuration order is not randomized, and a later revised protocol should randomize/block order before publication. Two-sample smoke CIs are not robust statistical evidence.

Memory is tracemalloc peak Python allocation per stage. Native bigint internals partially depend on interpreter accounting; native crypto allocations, JVM, other processes and Spark worker heaps are not fully tracked. CPU utilization, full RSS, worker spill/temp files and bytes transmitted are pending. The harness includes a bounded protected-output canary audit, not heap/log/swap instrumentation. A full exposure claim E=0 needs external execution-path audit and worker-level instrumentation.

NSL-KDD 500000 is skipped as unavailable, not duplicated. Public runs remain pending until inputs, SHA-256, Java/Spark environment, dependencies, correctness and practical run capacity are checked. No smoke result may be copied into the public-results tables.

Checkpoint resumption is per completed sample, not per encrypted record within a sample. Fresh-key execution sessions preserve independent randomization and secure key sizes. Each session records its environment and keygen; completed results are retained and only unfinished configuration/repeat pairs are run. Warmups repeat after process restart for unfinished configurations. Resumed sessions may introduce environmental drift; report session strata instead of assuming one uninterrupted trial. NYC source rows now stay in a dataframe until selected indices are chosen; only selected records become dictionaries.
